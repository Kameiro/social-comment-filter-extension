# 评论筛选助手

## 账户与数据同步

项目支持仅本地保存、同步到你的服务器、同步到商业客户自托管服务器三种模式。新安装版本默认使用 `https://comment-filter.04210410.xyz`；首次使用可在评论数据库页面注册或登录账户。已登录后，扫描和主页资料任务完成会自动同步，评论数据库页面只显示同步状态和最近一次成功同步时间。同步超时或中断时会显示“同步失败”，悬停状态可查看原因；本机数据仍保留，下次任务完成时会再次尝试。
重新加载扩展不会主动退出账户。打开数据库时先显示“正在确认登录”，不能把等待账户接口返回显示成“未登录”。校验在 15 秒内未完成时显示“连接待恢复”并保留本机令牌，可点击“重试连接”，网络恢复后也会自动重试；真正收到 401 时提示重新登录，也不会擅自清除令牌。同一浏览器的其他数据库页面登录或退出后，账户状态会更新，旧校验响应不能覆盖新状态。只有手动“退出登录”才会清除本机令牌。

服务端模板位于 `services/cloud-server`：

1. 使用 PostgreSQL 执行 `services/cloud-server/schema.sql`。
2. 复制 `services/cloud-server/.env.example` 为 `.env`，设置数据库地址和随机 JWT 密钥。
3. 在 `services/cloud-server` 中运行 `npm install`，然后用 `npm run provision -- 邮箱 密码 客户名称` 创建账户。
4. 通过 HTTPS 反向代理运行 `npm start`。
5. 在评论数据库页面注册或登录账户；首次登录后插件会自动同步本机数据库，用户不需要手动触发同步或清空数据库。

商业客户可以部署自己的 `services/cloud-server`，数据表按 `tenant_id` 隔离。云端服务现在支持可配置套餐、待支付订单、账户订阅状态和管理员手动授权；具体支付平台的服务端回调需要按商户配置接入，不能由插件前端自行确认付款。

收费联调时，先在云端管理后台创建套餐并配置 HTTPS 支付入口，再在插件账户窗口查看套餐和创建订单。服务端环境变量 `BILLING_ENFORCED=false` 时只联调流程不限制同步；完成支付回调验签、退款和撤销流程后，再设置为 `true` 正式启用授权校验。

这个项目包含电脑浏览器端和 Android 快手模块端。两端共用云端账户和数据模型；电脑端运行浏览器扩展，手机端运行 Vector/LSPosed 模块。电脑浏览器扩展用于筛选当前抖音、小红书或快手帖子页面已经加载出来的评论文本。

## 项目结构

```text
extension/                 浏览器扩展源码和 manifest
  background/              MV3 service worker
  popup/                   工具栏弹窗
  dashboard/               本地评论数据库面板
  content/common/          公共脚本、接口捕获、任务浮窗和私信
  content/platforms/       抖音、小红书、快手平台采集器
  data/                    IndexedDB 数据层
  cloud/                   云端同步客户端
services/                  Playwright、云端 API、Native Messaging 服务
scripts/                   安卓构建和 macOS 启动脚本
docs/                      安卓和 ZeroTermux 文档
dist/                      安卓扩展发布产物
```

平台采集器只放页面结构和平台差异；跨平台逻辑放在 `extension/content/common`，数据库操作放在 `extension/data`。修改桌面扩展后，通过 `scripts/build-helium-android.mjs` 生成 `dist` 中的安卓扁平包。

## 版本区分

- **电脑本机 Chrome/Chromium 版**：在 `chrome://extensions` 加载项目中的 `extension` 文件夹。本机测试弹窗、评论抓取和 Playwright 主页资料核验时使用这一版。
- **安卓 Helium/Titanium 版**：直接加载 `dist/helium-android-extension` 文件夹即可；`dist/helium-android-extension.zip` 只用于复制、备份或发布。这一版只给支持 Chrome 扩展的第三方 Chromium 浏览器加载。
- 修改电脑端源码后，运行 `node scripts/build-helium-android.mjs` 更新 `dist/helium-android-extension`；需要 ZIP 时，在 `dist` 目录执行 `zip -qr -FS helium-android-extension.zip helium-android-extension`。

## 安装

1. 打开 Chrome，进入 `chrome://extensions/`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择项目中的 `extension` 文件夹。
5. 打开抖音、小红书或快手帖子页面。
6. 点击 Chrome 工具栏里的“评论筛选助手”图标。

修改桌面版文件后，在 `chrome://extensions` 对电脑端扩展点击“重新加载”，再重新打开插件弹窗。

## 安卓平板（Helium / Titanium Browser）

可以使用。Helium Android 已更名为 Titanium Browser，本质上是支持 Chrome 扩展的第三方 Chromium 浏览器，可在 `chrome://extensions` 开启开发者模式后直接加载已解压扩展文件夹。

1. 在项目根目录运行 `node scripts/build-helium-android.mjs`，会生成 `dist/helium-android-extension` 文件夹。
2. 将整个 `dist/helium-android-extension` 文件夹复制到安卓平板；如果通过 ZIP 传输，再先解压，不要只复制里面的单个文件。
3. 在 Helium/Titanium 地址栏打开 `chrome://extensions`，开启 `Developer mode`，点击 `Load unpacked`，从系统文件选择器中选择该文件夹。
4. 在扩展管理页将“评论筛选助手（安卓）”固定到工具栏；打开抖音、小红书或快手帖子后，从工具栏打开插件。

安卓端可使用：抖音、小红书和快手评论抓取、关键词/IP 属地/日期筛选、接口分页和复制结果。评论数据库的“发现帖子”自动搜索需要电脑端独立 Playwright 后台服务，安卓端暂不启动主浏览器外的搜索任务。

安卓端不提供：主页性别、年龄、所在地核验；删除已确认男性；按目标女性人数停止。这些功能依赖电脑上的本地 Node/Playwright 服务，Android 浏览器无法运行该服务。批量任务会逐个打开帖子，移动端浏览器可能会因后台页面节流而比电脑端慢，建议一次处理少量链接。

详细的平板安装、首次测试和排错步骤见 [安卓使用说明](docs/ANDROID.md)。

快手 App 内嵌采集模块的 Vector 源码、构建和诊断说明见 [`android/kuaishou-collector`](android/kuaishou-collector/)；它与 Chromium 扩展是两套独立运行时。

需要在平板本机准备后续性别核验所需的后台浏览器环境时，参见 [ZeroTermux 最短教程](docs/TERMUX.md)。当前教程只做环境验证，不会改变插件的评论抓取功能。

## 使用

- `批量帖子链接` 留空：扫描当前打开的帖子。
- `批量帖子链接` 填多行：一行一个抖音、小红书或快手帖子链接，插件会逐个打开、扫描、关闭，并合并结果。
- 评论任务只接受具体帖子详情链接（抖音 `/video/数字`、`/note/数字` 或带 `modal_id` 的帖子链接，小红书 `/explore/帖子ID`，快手 `/short-video/ID`）；搜索页不能直接作为评论任务。队列出队时也会再次校验，单个无效链接只会记录明确失败原因，不会让后续排队任务一起失败。
- “评论数据库”后台的“发现帖子”页：输入关键词后，插件会交给独立的 Playwright 后台浏览器打开抖音搜索页，监听抖音自己的搜索响应，提取帖子数据并去重；不会在你当前使用的浏览器中打开搜索标签页。结果会和历史搜索结果合并保存。你可以查看点赞、评论、转发、收藏和是否已经抓取过评论，再勾选帖子批量抓取评论及用户资料。该功能不需要第三方 API 或额外令牌。
- 自动发现支持抖音和小红书，使用搜索页自然加载和有限滚动。发现页上方只保留“发现关键词”；已保存结果有单独的筛选框，不会把列表筛选误当成平台搜索。关键词输入支持回车启动。
- 在“发现帖子”或帖子列表勾选帖子后，点击批量抓取会先打开“批量抓取条件”窗口，可修改评论关键词、排除词、评论 IP 属地、最近天数、性别和条件关系；“抓取上限”可设置每帖页数与目标人数，默认 `0` 为全部。确认后才创建任务，任务管理可展开“抓取条件”查看提交时的快照。取消、点击窗口外部或按 Esc 不创建任务；提交失败保留输入。勾选“保存为默认抓取条件”后才更新下次默认值。评论、回复与用户资料沿现有流程获取，结果追加保存。
- 发现任务在“任务管理”中显示平台、关键词、加载轮数、接口响应数和解析数量；登录和验证作为暂停状态显示在正在执行中。同一搜索不会并发创建重复任务，其他搜索需等待当前发现结束。发现结果由后台保存，离开发现页不影响保存。
- 评论任务历史显示本次任务实际读取的评论数、本次命中数、每个帖子成功/失败/未确认数量，以及接口失败、分页中断、验证和回复缺口等诊断；不再把本地数据库的全局评论总数当作本次任务数量。
- 评论失败重试会检查原任务和重试来源关联的帖子记录，保留具体帖子 ID 并转换搜索弹层链接；不能恢复完整帖子集合时拒绝重试，避免只重跑一部分。原评论阶段已确认到末页、仅主页资料未完成时，同条件重试只补读失败用户，不重新抓评论。主页失败原因保存在任务诊断中。重试前会核验当前扩展后台的任务引擎版本；只刷新数据库页面不足以加载后台代码，需要在浏览器扩展管理页重新加载扩展。
- 独立发现浏览器与其验证窗口使用同一个持久化目录。遇到登录或验证时保留独立窗口，只有收到正常搜索数据并确认页面恢复后才继续；不会改用你的主浏览器绕过验证。达到加载上限或页面停止增长不等于平台明确返回末页。
- “等待平台验证”只用于实际可见验证或接口明确要求验证；隐藏验证控件、帖子文字与作者认证字段不会触发。页面正常时显示“等待搜索数据”，超过 30 秒没有可解析数据就结束等待并保留窗口，不再让你等待不存在的验证码。可见窗口收到的帖子直接用于当前任务；任务历史显示搜索接口 HTTP 状态与页面是否显示验证。此修复要求后台发现引擎 `3`，旧后台会提示重启。
- 快手帖子通常使用 `https://www.kuaishou.com/short-video/{photoId}` 格式；快手短链请先在浏览器中打开并等待跳转到完整帖子页，再复制最终地址。快手当前只处理页面已经加载的评论，不会模拟滚动；快手接口分页暂未接入。
- 结果里会带上 `帖子链接`，方便复制后区分评论来自哪个帖子。
- 抖音从搜索结果弹层打开的地址（例如带 `modal_id` 的 `/search/...` 或 `/jingxuan?...`）会自动转换成可直接打开的帖子地址 `https://www.douyin.com/jingxuan?modal_id={modal_id}`；原搜索页只作为来源页保存，不会再写入评论的帖子链接。扩展启动时也会迁移旧任务和队列中的这类链接。
- 支持关键词、排除关键词、IP 属地、最近天数、接口页数上限、追加/重新搜索。接口页数上限为 `0` 时表示读取到平台明确返回没有下一页；目标性别人数为 `0` 时表示不因命中数量提前停止。抖音继续复用当前页面的评论请求模板分页。小红书不修改旧请求的游标或重放旧签名：通过帖子自身的正常滚动加载下一页，并捕获网页实时生成的新接口响应；第一页直接使用已捕获结果，不会改成 `cursor=0` 后重发。任务会读取页面公开访问参数用于诊断，但不会把访问参数写入日志或固定保存。评论和回复全部按评论 ID 去重，接口失败或网页不再加载时保存现有数据并标记未完成。
- 评论量较大时，抖音主评论页、回复线程和资料核验都会持续刷新任务心跳；单个回复线程不会因为超过旧的短超时被误判为卡死。后台看门狗现在只作为较长时间无心跳时的最后保护，队列中的后续任务会在前一任务真正结束后依次启动。
- 小红书任务只有接口明确返回末页才显示“已确认到末页”。没有捕获评论接口、接口中途失败或回复未加载完时，已取得的评论仍会保存，但帖子和任务管理会标记“抓取未完成”，任务详情会显示接口页数和停止原因；按条件更新遇到此类缺口会保留原有帖子数据，不用少量新结果覆盖旧数据。旧任务没有分页审计时无法根据已保存条数反推是否抓完，请重新抓取核实。
- 电脑端评论任务使用当前浏览器登录会话的独立正常采集窗口，窗口不抢焦点、不切换已有标签页；查看帖子页与采集页分离，关闭查看页不影响任务。小红书网页在隐藏标签页中不会继续自然分页，因此不能把采集窗口最小化或隐藏；隐藏后任务会显示“等待采集窗口可见”，而不是误报空结果或末页。普通采集结束后只关闭自己的采集页，登录或验证码页面保留供用户处理。意外关闭采集页时桌面端会重新打开当前帖子并保留已保存结果，丢失的页面上下文可能需要重读当前帖子。安卓端仍使用当前帖子页面，分页时需保持页面可见，关闭浏览器无法保证继续执行。更新后重新加载扩展，新任务使用任务引擎 `5`、V3 消息和 `3.4` 小红书分页引擎，诊断评论容器会返回版本、页链和停止原因。
- 数据库中的抓取审计只有在接口明确返回 `has_more=false`、等价的 `hasNext=false` 或 `no_more` 游标时才显示“已确认到末页”。接口字段缺失、游标重复、游标缺失、页数上限、验证码和接口失败都会显示“未确认到末页”，不会把部分结果误报为完整。
- 接口读取不会绕过登录、验证码或平台限流。抖音网页请求会带页面实时生成的签名参数，小红书评论接口也依赖页面会话，因此插件捕获当前页面已经发出的真实请求，不保存固定签名，也不直接拼接长期失效的接口地址。
- 如果接口分页触发平台人机验证，任务会暂停为“等待平台验证”，保存已经获取的评论并保留当前帖子页面，不会自动关闭验证页，也不会继续重放接口。请在当前页面手动完成验证，再点击浮窗或插件弹窗中的“验证完成，继续抓取”；恢复使用原任务编号并按评论 ID 去重。
- 小红书一级评论末页确认后，逐组使用网页的“展开回复”加载二级评论，捕获对应的回复接口响应。所有一级评论都检查回复，不能只展开符合筛选条件的父评论；最终按每条评论自身的地区、时间、关键词和公开性别筛选。一级评论及每组回复都明确读完才标记完整；只到一级末页但仍有未展开回复时显示“抓取未完成”。每组回复失败最多重试三次，未读完的组数会保留在任务审计中。
- 小红书分页引擎 `3.4` 使用保守限速：滚动、展开回复及扫描时的主页核验共用至少 5 秒的操作间隔，扫描时主页核验一次只提交 1 位用户，每读取 20 页休息至少 30 秒；回复失败按 15/30 秒等待后重试。移除底部反复回弹和合成滚轮事件，不伪装真人轨迹、不修改浏览器指纹或绕过平台限制。主评论接口失败后不继续请求回复和用户资料。
- 小红书评论/回复接口返回 HTTP 403、406、429 或明确的频繁访问/账号限制错误时，立即暂停采集并保存当前结果。小红书评论队列也会暂停，停止当前任务或重新加载扩展不会解除这个保护；队列仍按提交顺序保留，不会把暂停误记成任务失败。任务管理显示“小红书采集已暂停”，请先在平台确认账号恢复正常访问，再点击“确认账号已恢复”或“账号恢复后继续”。解除暂停是用户确认，不代表程序能自动判断封禁已解除；平台仍拒绝请求时会再次暂停。这些间隔是本工具的保守默认值，不是平台官方安全额度，也不能保证账号不被限制。
- 如果平台明确提示封禁、封号或账号禁用，即使 HTTP 状态为 200，也会按失败响应内容暂停。已经封禁的账号不能作为测试账号；平台恢复账号前不要点击继续，不自动换号、换浏览器身份或尝试绕过封禁。随机操作轨迹不能解除已有封禁。
- 扫描结果会同时保存到当前浏览器的 IndexedDB 本地数据库；点击“打开评论数据库”可按帖子、评论和用户查看、搜索、筛选和复制。旧版 `chrome.storage.local` 结果首次打开数据库时会自动迁移。
- “评论”页会标明一级评论或二级评论；抖音、小红书按主评论/回复接口和明确的嵌套关系识别，小红书已加载的回复也可由页面结构识别。无法核实层级的旧记录及快手页面记录显示“层级未知”，重新抓取可补全有接口依据的记录。
- 在“评论数据库”的“用户”页可以点击“私信”。插件会根据该用户最近评论过的帖子和评论生成可编辑草稿，确认后在后台打开用户主页并尝试发送；成功后会记录为“已私信”，避免插件重复发送。这个状态只代表本机插件记录，平台外发送的历史不会自动同步。
- “评论”页暂不显示批量私信入口；批量选择和发送流程尚未完成，避免误以为已发出。已有用户资料的评论可直接使用单人“私信”按钮，也可在“用户”页逐个确认并发送。
- 抖音私信复用已登录网页的 IM SDK，打开会话后直接发送，不再模拟输入和点击发送按钮；电脑端与安卓 Chromium 扩展使用同一流程。平台 SDK 仍依赖浏览器登录状态，并非无需登录的独立接口。目标会话不一致、SDK 不可用或历史中已有相同内容时不会发送；发送结果不明确时保留聊天页且阻止重试，请先检查聊天记录。小红书和快手暂时保留页面操作方式。
- 本地 IndexedDB 是当前浏览器的缓存；登录默认云端账户后，扫描和主页资料任务完成会自动同步到服务器，电脑端和安卓端可以通过同一账户使用云端数据。
- 抖音主页资料默认由独立 Playwright 后台浏览器读取，不会打开或导航你当前使用的浏览器；该后台浏览器使用自己的持久化登录状态，未登录或遇到安全验证时会明确暂停任务。只有显式选择浏览器读取模式才允许使用当前浏览器。小红书仍优先复用扩展所在 Chromium 会话，访问参数原样保留；普通临时页使用非活动标签，不抢占前台，登录或验证页会保留并提示阻塞原因。
- 当前会话无法读取时才回退 `services/playwright-worker`。服务默认先探测本机 Chromium 的 CDP 调试端口 `9222`，连接不到时使用独立浏览器。抖音会监听主页自身发出的 `/aweme/v1/web/user/profile/other/` 响应并严格核对目标 `sec_uid`，同时支持公开 SSR/DOM 资料；小红书读取公开资料区。解析器以完整脚本注入，避免序列化单个函数导致辅助函数丢失；页面跳转造成的上下文销毁只重试一次。扩展请求超时覆盖服务的导航、等待和重试时间。CDP 模式不会因缺少登录态而关闭用户浏览器。

### Playwright 登录与平台验证

主页资料任务遇到登录或安全验证时会进入“等待登录/等待验证”，并打开独立的可见 Playwright 窗口；完成后在任务管理点击“登录完成，继续”或“验证完成，继续”，任务会从当前用户继续。远程服务器上的可见窗口不会自动出现在本机，必须通过受保护的 noVNC、VNC、RDP 或远程浏览器控制台操作。远程 worker 默认只监听 `127.0.0.1:38765`，不要直接暴露 CDP、Cookie 或浏览器数据目录。完整部署要求见 [`docs/PLAYWRIGHT-AUTH-REMOTE.md`](docs/PLAYWRIGHT-AUTH-REMOTE.md)。
- 性别只读取平台字段或公开图标，年龄只读取公开资料标签；IP 属地和主页所在地独立保存，主页 IP 不覆盖历史评论 IP，也不当成所在地。抖音成功资料缓存 24 小时，但仅性别的快速检查不能代替后续完整资料补充。未填写、隐藏或不可访问的信息保留未知/空白，不从头像、昵称或评论猜测。任务实时显示成功数、失败数及最近失败原因；登录、验证或旧解析器错误会中止本次资料补充，避免把同一个服务错误累计到所有用户。
- 点击“开始扫描”后，任务由扩展后台继续运行；关闭插件弹窗不会停止任务。
- 评论抓取可以连续提交多个任务：同一浏览器内按提交顺序排队执行，每个任务在提交时获得独立编号。评论数据库的“任务管理”可按类型查看当前帖子、接口抓取消息、命中数、资料补充状态、队列位置和完成/中断历史；批量帖子与评论更新也沿用此队列。发现帖子、批量更新用户资料和保存用户分析范围会记录实际执行结果。批量私信尚无可用执行器，任务管理会明确标示不可执行，不会显示为已经发送。
- 用户分析的帖子范围只按选中帖子、帖子关键词、平台与发布时间筛选。“用户/评论地区”只匹配用户所在地、主页 IP 属地和评论 IP 属地，不要求帖子标题包含地区。选择女性/男性时仍只统计已明确识别对应性别的用户；未知不会自动归类。点击“重新计算”会应用并保存当前表单条件。空结果区分未匹配帖子、没有已保存评论与用户条件未匹配；旧帖子缺少发布时间时保留在范围内，并显示未记录数量，不能据此确认它发表于指定天数内。
- 用户列表的评论数可点击，进入该用户全部已收集评论的明细；通过主页身份精确匹配，不把主页字符串相似的其他用户混入。明细保留评论层级、点赞、回复、时间、IP 和原帖链接，可继续按帖子、任务和关键词筛选。“返回用户列表”保留原搜索和勾选状态，“全部评论”解除用户限定。用户分析的“评论”入口也使用同一明细视图。这里只展示本机数据库已收集的评论，不代表该用户在平台上的全部历史评论。
- 用户列表与用户分析表的昵称直接链接到对应主页，在新标签页打开；不再单独显示“主页”操作按钮。
- 用户列表新增平台列，并支持平台、性别、IP 属地、年龄区间与“最后出现”时间的新旧排序。主页 IP 筛选只使用明确保存的 `profileIpRegion`；最近评论 IP 来自该用户时间最新的已收集评论；“任一 IP”同时兼容历史 IP 字段。多个 IP 条件用逗号或顿号分隔，任一匹配即可。年龄范围只使用明确的数字年龄线索，未知默认不计入范围，可勾选“含未识别年龄”；年代、生日、区间和带加号的线索不猜测成具体年龄。没有时间的记录在两种排序中均放末尾。选择全部、反选与复制均使用当前筛选结果；其他筛选下已经勾选的用户仍保留，显示总选中和当前可见数量。
- 失败、资料未完成和抓取未完成的历史任务可点击“重试任务”。发现、评论抓取、帖子更新、主页资料与批量资料更新复用原任务参数，创建新编号并显示来源任务；原失败记录保留。评论重试按追加去重合并保留旧数据，帖子更新仍只在完整成功后替换。连续点击或已有相同任务执行/排队时不会重复创建。旧记录尽量从帖子筛选任务恢复条件，缺少原参数或没有执行器时明确显示不能重试的原因，不改用当前筛选条件。
- 同一帖子集合、筛选条件和任务类型的请求，如果正在运行或已排队，会返回已有任务编号，不再重复创建；任务结束后仍可主动重新抓取。主页资料任务有独立启动锁，快速重复点击也不能创建两个执行实例。任务管理的“全部”视图以评论任务为总任务，将关联资料执行器作为子阶段展示，不显示两个重复任务卡；按资料类型筛选时可单独查看资料子任务。
- 运行进度分开显示帖子扫描、评论翻页、回复分组和完整主页资料补充；筛选时的小批量性别核验单独标记，不能当成完整资料已补完。未知总页数只显示已读页数及末页确认状态，不估算整体百分比。多帖子任务可展开每个帖子子任务，展开状态在进度刷新时保留；用户资料阶段分别显示已处理、成功和失败数量。平台验证或隐藏采集窗口时显示暂停，不继续播放运行进度。
- 任务管理按编号、状态、进度和审计信息分层展示；历史任务保留完整说明但默认折叠长消息，链接展示不含访问令牌的帖子路径，最近任务优先显示，更早记录可展开查看。
- 评论数据库的帖子列表优先显示标题、平台、已存/平台评论数和最近抓取时间；点击标题可打开原帖，原帖链接、发现来源与删除入口放在每条帖子的“更多”中。后台服务状态常驻标题旁，启动、重启、安装和状态刷新可展开使用；点击面板外部或按 Esc 会折叠面板，点击内部按钮不会自动折叠。
- 帖子右侧的任务浮窗按平台与帖子 ID 关联，只显示本帖的读取、命中和主页资料进度；没有关联任务的页面不显示浮窗。关闭查看页后再次打开同一帖子，浮窗会从后台状态恢复；搜索弹窗内切换帖子也会重新匹配。历史记录保存分帖统计，停止、继续和复制结果都限定到关联任务；多帖任务的停止按钮明确显示“停止整个任务”。浮窗仍可拖动、吸附和收起。安装更新后请在当前任务结束时重新加载扩展，并刷新查看页；不要在运行中重新加载，以免中断任务。

## 说明

主页性别核验首次返回“独立后台浏览器尚未登录”时，服务会自动启动一次可见登录窗口。完成抖音登录后，回到评论数据库点击“按此条件更新”或“补充主页资料”重新执行；旧任务不会把登录前的“未知”自动改写成已确认性别。登录失败、验证码或主页未公开性别时，任务会保留“未知”并显示具体失败原因。

更新资料解析代码后，应在数据库后台服务面板点击“重启”，并在浏览器扩展管理页重新加载扩展。旧服务报 `ReferenceError: ... is not defined` 时不能继续批量尝试；服务健康状态中的 `profileParserVersion` 为 `3` 才代表已载入本次解析器。重新加载不会清除平台登录 Cookie、本地数据库或账户令牌。

主页资料的后台回退会先核对解析器版本：缺少版本或低于 `3` 的服务会明确提示更新，并停止资料任务。重启操作还会核对 `workerStartedAt` 是否变化，不能仅凭旧进程仍返回 HTTP 200 就提示重启成功。主页已完整读取但没有公开性别时，不在同一次读取中反复打开；补读遇到登录或安全验证必须向任务传递阻塞原因。

后台健康状态另外检查 Playwright 浏览器文件是否存在且可执行，使用 `browserRuntimeReady` 区分“后台进程在线”与“浏览器组件可用”。缺失时插件和数据库显示“浏览器组件缺失”，请使用“安装 / 修复”；不会把启动失败当作用户资料未知。可见登录窗口与后台读取使用相同的完整 Chromium 程序，避免安装了完整浏览器却缺少独立 headless shell。服务启动不再预先连接你的浏览器或打开页面，抖音主页读取在服务端也强制使用独立持久化目录。

浏览器组件默认安装到应用专用数据目录：macOS 为 `~/Library/Application Support/CommentFilter/playwright-browsers`，Windows 为 `%LOCALAPPDATA%/CommentFilter/playwright-browsers`，Linux 为 `$XDG_DATA_HOME/CommentFilter/playwright-browsers`（未设置时使用 `~/.local/share`）。安装器与服务使用同一路径，不再依赖系统缓存 `ms-playwright`；可通过 `PLAYWRIGHT_BROWSERS_PATH` 显式覆盖。浏览器组件目录与原有登录数据目录分离，修复组件不会删除登录状态。资料任务重试只补充失败或尚未处理的用户，已成功用户保留；旧记录若无法确认成功范围才重读原列表。

浏览器组件缺失、浏览器启动失败或后台不可连接属于整批服务故障：完整资料补充在第一次此类错误后停止，不会继续把数百用户记成同样失败。扫描中的性别核验则保存已读评论并暂停为“后台待修复”，修复后点击“修复后台后继续”，从原用户核验阶段继续，不把服务错误缓存成资料已读取。
手动补充选中用户时会刷新资料，不跳过已有性别、年龄、所在地的用户，也不命中 24 小时缓存；自动补充会另外检查主页 IP 是否需要回填。

- 只读取当前页面已经展示或自然加载出来的公开评论数据。
- 不保存固定接口签名，不逆向签名参数，不绕过登录、验证码或平台限制。
- 抖音、小红书和快手页面结构都可能变化，如果某个平台突然抓不到评论，先点“诊断评论容器”，把输出结果发给我继续微调。

## Playwright 后台服务

首次安装依赖仍需执行一次：

```bash
cd services/playwright-worker
npm install
node install-browser.mjs
```

安装依赖后，先双击 `scripts/mac/安装自动后台服务.command`。安装脚本会安装 `~/Library/LaunchAgents/com.commentfilter.playwright-worker.plist`，让 Playwright 后台服务在登录 macOS 后自动运行，并把 Native Messaging Host 注册到 Chrome、Ego Lite、Chromium 和 Edge 作为备用启动方式。这样插件只要能安装在 Chromium 系浏览器中，就可以连接本机 `127.0.0.1:38765`，不依赖浏览器是否支持 Native Messaging。要让服务的资料回退读取复用当前浏览器登录态，仍可让 Ego/Chrome 开启本机远程调试（默认端口 `9222`）。发现帖子始终使用独立的持久化浏览器，其登录和验证不切换到主浏览器。设置 `COMMENT_FILTER_BROWSER_MODE=cdp` 可让资料回退只使用共享浏览器，设置为 `isolated` 可强制使用独立后台浏览器。若要停止常驻服务，可执行 `launchctl bootout gui/$(id -u)/com.commentfilter.playwright-worker`；重新运行安装脚本即可恢复。
