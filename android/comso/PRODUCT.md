# 快手内嵌采集模块

<!-- impeccable:product-schema 1 -->

## Platform

android

## Users

用户在自己已登录的快手 App 中发现作品、收集公开评论和主页资料，并在结果中筛选、分析及手动查看用户。

## Product Purpose

将现有浏览器评论收集工具的核心功能迁移到快手手机版模块，管理入口内嵌到快手 App，功能通过可复用接口提供。
首要验收是手机版公开评论的 IP 属地、可靠翻页与回复完整性，而不是只完成框架或界面安装。

## Operating Context

开发环境为 Android 16 ARM64 模拟器、Magisk、Zygisk Next、Vector API 102。
目标真机为用户的一加 13T / Android 16 / ReSukiSU / Vector，尚未真机验收。
用户明确要求自主继续开发；现有浏览器版的数据口径、筛选与任务管理是功能参照，不以浏览器页面嵌入代替原生实现。

## Capabilities and Constraints

公开评论需保存作品与用户关联、一级/二级、父评论、文本、评论时间、真实点赞/回复和手机版接口公开的评论地区。
接口与 UI 共用数据和任务服务。任务有独立统计、错误记录、暂停/继续及去重，未知末页不能算完成。
性别、年龄、主页所在地与主页 IP 只来自公开资料，未知值不能猜测或写成确认成功。
登录、验证码与平台限制需保留给用户处理；不自动群发私信。手机自然加载依赖 App 前台，不宣称关闭 App 后仍能无限加载。
本机接口需要认证，仅监听回环地址；不对公网开放采集数据和账号。

## Evidence on Hand

本机实际 Hook 探针已执行；固定真实任务保存 117 条（102 条一级、15 条回复），115 条地区非空，五个回复组末页已确认。
原生搜索三页发现 30 条作品，两位公开主页补充成功；平台评论数 124 与抓取数差 7 条，年龄及折叠评论仍有验收缺口。
内嵌 UI、正常分页、折叠流及真机验收分别记录，不能以样例或单元测试冒充全量完成。

## Product Principles

- 先确认平台真实数据和分页证据，再显示成功。
- 采集、筛选和展示分离，所有 UI 操作由统一接口处理。
- 保留用户数据与登录状态，暂停不重置已完成阶段。
- API 默认本机且经过认证，不保存账号认证参数。
- 管理界面遵循 Android 原生操作习惯，信息可扫描且系统返回正常。

## 双端账户与操作更新（2026-11-01）

浏览器扩展与快手模块共用云端账户，但不共享平台登录态或本机接口密钥。手机面板的“登录账户”入口通过 `CloudAccountClient` 登录同一服务，令牌只保存在模块私有数据库并用于 HTTPS 请求；任务完成后自动同步，账户面板可手动重试。统一契约见项目根目录的 `UNIFIED_PRODUCT.md` 和 `docs/CLOUD-ACCOUNT.md`。

采集条件面板新增 `pagingMode`：自动（优先原生）、原生接口、页面滚动。任务仍以实际 `pagingDriver` 与 EOF 证据判定完成，选择项只是操作意图，不会把 UI 滚动冒充原生分页。
