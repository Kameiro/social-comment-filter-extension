## 本次定位

1. 旧 CommentResponse 没有 mHasMore，仅按字段读取会永久缺失末页。
2. 评论列表位于不获取焦点的弹窗，严格焦点筛选导致不滚动。
3. 回复有网络返回和缓存读取两条路径；需绑定真实作品/父评论，子回复 EOF 不能终止主流。
4. 后续任务只排队，不立即争抢当前页面；平台阻塞需显式继续。
5. API 位于模块进程，与快手 UI 解耦；Android 仍可能回收进程，打开管理页可恢复。
6. 第三方 DTO 的可变 hashCode 会抛异常，去重缓存改用弱身份键，不调用其 hashCode/equals。
7. NanoHTTPD 在未指定 JSON charset 时默认 US-ASCII；服务端和客户端统一 UTF-8。
8. 不把上次读到的作品误标为“当前作品”；新建任务先确认作品 ID，再弹出条件。
9. 数据库全屏面板会暂缓自动翻页；创建任务后关闭面板回到快手，避免任务看似运行却被自己的面板阻挡。
10. 页面销毁时释放 Dialog 与轮询；旧 Dialog 的延迟关闭回调不能清除新 Dialog 引用。
11. 真机截图“4 条全是回复”对应的模拟器对照：旧版先打开评论再建任务 #9（auto=false），保存 28 条回复、0 主评论、总数未知。主评论首页发生于任务创建之前；之后缓存回复仍被读取，不能只依赖重新触发回复 getter。
12. 0.1.1 在新任务检查主评论页数，必要时重新打开目标作品；无主评论页也受超时检查。短期缓存只接受已知起始游标与连续页，不把未知游标、尾页、回复页回放为首页。
13. 数据源和任务控制是两件事：已适配版本直接调用 App 内存中的原生 KMP 分页器，并从原生响应保存数据；`ui` 模式仍保留为兼容回退，本机 HTTP API 只提供数据库和任务控制。

私有截图、数据库、APK、日志和导出保存在 runtime/collector/，不作为公开文档附件。
